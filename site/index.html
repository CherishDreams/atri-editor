它把力气花在哪

        

          不是把上游命令包一层按钮，而是把「用完之后数据还在不在」当验收标准。
        

        

          

            
Markdown 全链路往返

            

              表格与单元格对齐、任务列表、围栏代码块的语言、图片与附件，全都能导出去再载回来。
              往返做了逐字节幂等：导出 → 载入 → 再导出，两份完全相同。
            

            getMarkdown() / setMarkdown()
          

          

            
导出丢失报告

            

              序列化器对没钩子的类型是静默丢弃。现在导出之前可以先问一遍：哪些节点、哪些标记、
              哪个属性会消失，各丢几处。
            

            getMarkdownLosses()
          

          

            
上传管线

            

              逐文件进度、失败重试、图片 base64 兜底，上传中不污染撤销历史。 保存前问一句
              hasPendingUploads()，避免把本地预览地址写进内容。
            

            uploadFiles() / retryFailedUploads()
          

          

            
表格

            

              网格选择器插入、行列操作菜单、列宽拖拽，Markdown 一侧是可读的 pipe table；
              合并单元格与列宽这类 pipe table 表达不了的东西，会如实进丢失报告。
            

            insertTable()
          

          

            
主题与多语言

            

              亮/暗主题、中英文开箱可用，主题色走 CSS 变量。语言包可以自己注册，
              每个编辑器实例互相隔离。
            

            setTheme() / addResources()
          

          

            
代码高亮是独立包

            

              highlight.js 的体积不该由每个使用者承担。高亮单独成包，语法库按需引入，
              不装就只有代码块、没有着色。
            

            @atri-editor/code-highlight
          

        

      


      

        
三行接进来

        

          

            
安装

            
npm install @atri-editor/core

          

          

            
使用

            
import { AtriEditor } from '@atri-editor/core';
import '@atri-editor/core/styles';

const editor = new AtriEditor({
  element: '#editor',
  content: '# Hello',
});

          

        

        

          也可以直接用自定义元素：<atri-editor theme="dark"></atri-editor>， 导入包即自动注册。Vue、React 的接法见 在线 Demo 与
          demos。
